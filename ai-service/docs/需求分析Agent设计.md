# 需求分析 Agent 设计

> 说明：本文档是需求分析 Agent 的**设计参考（源）**。Agent 实际运行时吃的是从本文档
> **蒸馏出的系统提示词**（见 `requirement_analyst.py` 的 `ANALYST_SYSTEM_PROMPT`）；
> 而《指标体系方法论》则放在 **RAG 向量库**里，Agent 按需 `search_knowledge` 检索。
> 分工：知识进 RAG（用到再查），行为进提示词（每轮生效）。
>
> 落地定位（轻量版）：产出以**指标详细口径**为主体，表只给一行方向性建议、交由数仓开发确定；
> 交互尽量轻，只抓真正影响口径的模糊点，目标把需求准确度提升 80~90%。

## 1. 目标

需求分析 Agent 的目标，是基于指标体系方法论，把业务同学提出的模糊需求，拆解成数仓研发能够理解和执行的需求说明。

它不是直接写 SQL，也不是直接判断落表，而是先完成需求分析、指标拆解、口径澄清、数据资产定位和研发输入整理。

核心目标：

- 识别业务需求真正想解决的问题
- 拆解需求中的指标、原子指标、修饰词、时间周期、维度和粒度
- 明确指标口径、时间口径、过滤条件和限制条件
- 找出可能使用的 DWD、DWS、DIM、DWM、ADS 表
- 判断是否存在标签、维度、汇总指标或宽表缺口
- 用业务能理解的语言复述指标口径，让业务确认
- 输出研发能直接评审和开发的需求说明

## 2. 输入

Agent 的输入通常是一段业务口语化需求。例如：

```text
我想看一下新客余额，按渠道和产品分一下，最好能每天更新。
```

或者：

```text
最近放款质量感觉有点问题，想看不同月份放款用户在第 1、3、6 个月的逾期情况，再按渠道和授信金额段拆一下。
```

这类需求通常存在问题：指标名称不清晰、指标类型不明确、原子指标不明确、修饰词口径不明确、时间周期不明确、维度和修饰词混在一起、粒度不明确、数据来源不明确、过滤条件不明确、是否临时分析或长期看板不明确。

Agent 要做的事情，就是把这些模糊点拆出来，并推动业务确认。

## 3. 总体流程

```text
1. 识别业务目标和需求类型
2. 提取候选指标
3. 拆解指标类型
4. 拆解原子指标、时间周期、修饰词
5. 区分修饰词、维度、过滤条件
6. 确认时间口径、状态口径和数据限制条件
7. 判断统计粒度
8. 匹配可能使用的数据表
9. 判断是否存在数据资产缺口
10. 用自然语言复述指标口径，让业务确认
11. 输出研发可执行需求说明
```

## 4. 第一步：识别业务目标和需求类型

需求来了之后，不要一上来直接拆指标。第一步要先判断业务目标：业务想解决什么问题、是监控/分析/归因/对账/看板/临时取数还是沉淀模型、是一次性分析还是长期固定看板、是已有指标口径复用还是新指标建设。

示例 `看新客余额` 可能对应不同目标：临时分析（DWD + DWS 关联出数）、固定看板（可能落 ADS）、高频灵活分析（可能用/建 DWM）、标签缺失（可能先补 DWS 新客标签）。

## 5. 第二步：提取候选指标

从业务描述中提取所有可能的指标。示例 `不同月份放款用户在第 1、3、6 个月的逾期情况` 候选指标可能包括：放款用户数、放款金额、逾期用户数、逾期本金、用户逾期率、金额逾期率。

注意：业务说的"情况""表现""质量"通常不是指标，需要继续拆；比率类指标要拆分子分母；金额类要确认金额口径；用户类要确认去重规则。

## 6. 第三步：拆解指标类型

### 6.1 事务型指标
衡量业务活动发生情况。例：放款金额、支付订单数、还款金额、申请用户数。

### 6.2 存量型指标
衡量某个时点或截至当前的状态。例：当前余额、当前库存、当前在贷余额、当前授信用户数。
余额、库存这类要看来源：业务系统直接产出、数仓仅同步使用 → 存量型原子指标；数仓基于其他过程指标加工得到 → 存量型派生指标或汇总指标。

### 6.3 复合型指标
由多个指标组合计算。例：转化率、逾期率、占比、人均金额。
必须明确：分子、分母、分子分母是否来自同一统计范围、分母为 0 时如何处理。

## 7. 第四步：拆解原子指标、时间周期、修饰词

```text
派生指标 = 原子指标 + 时间周期 + 修饰词
```

- `近 30 天新客支付金额` → 原子指标=支付金额，时间周期=近30天，修饰词=新客
- `MOB3 DPD30+ 逾期本金` → 原子指标=逾期本金，时间周期=MOB3，修饰词=DPD30+

拆解后继续判断：原子指标来自哪个业务过程、时间周期按哪个时间字段、修饰词是标签/状态字段/属性字段还是临时条件。

## 8. 第五步：区分修饰词、维度、过滤条件

这是需求分析中最容易出错的部分。

- **修饰词**：指标口径的一部分，影响指标定义。例：新客、首贷、支付成功、DPD30+。
- **维度**：分析和下钻角度，通常用于 GROUP BY 或筛选。例：渠道、产品、地区、授信金额段、风险等级。
- **过滤条件**：数据范围限制。例：排除测试用户、只取成功放款、只取有效订单、排除取消/退款/作废/核销。

判断：这个条件是指标口径的一部分？还是分析维度？还是数据过滤？如果只是分析角度，不要轻易固化成新的派生指标。

## 9. 第六步：确认时间口径

统计周期（日/周/月/近N天/MOB/截至当前）、时间字段（创建/支付/放款/还款/快照）、归属方式（自然日/业务日/月末快照/T-1）、是否历史回溯、未成熟周期如何处理。

示例 `第 3 个月逾期率` 必须确认：是 MOB3 吗、是放款后满90天还是第3个账期、是第3个月月末状态还是第3个月内曾经逾期。

## 10. 第七步：确认数据限制条件

在确定使用表之后，判断表内是否需要额外限制条件：只取成功状态、排除测试、排除取消/退款/作废/核销、只取有效用户、只取当前快照、去重、排除异常样本、按产品/渠道/租户/业务线过滤。这部分要单独输出，不能藏在 SQL 里。

## 11. 第八步：判断统计粒度

明确一行数据代表什么。格式：`每个 X + Y + Z 一行`。例：`每个日期 + 渠道 + 产品 一行`、`每个放款月份 + MOB + 渠道 + 授信金额段 一行`。

## 12. 第九步：确定分析维度

维度单独列出：维度名称、维度口径、维度来源表、是否属性维度还是统计型标签。常见：日期、渠道、产品、地区、用户类型、授信金额段、风险等级、MOB。
风险等级看来源：业务系统维护的静态/准静态属性 → DIM 或用户主题属性；核心业务系统内部打出的业务类数据或模型/规则/统计加工得到 → DWS；外部采购的属性补充 → 按属性类信息管理。

## 13. 第十步：匹配可能使用的数据表

分别列：原子指标来源表、修饰词来源表、时间周期来源字段/表、维度来源表、标签来源表、可能需要的宽表、可能需要的 ADS 输出表。

示例：
```text
原子指标：余额  → DWD 借据明细表 / DWD 借据余额快照表
修饰词：新客   → DWS 用户标签表
维度：渠道、产品 → DIM 渠道表、DIM 产品表，或 DWM 用户资产宽表
```

Agent 不一定直接拍板，只需列出候选表和判断依据供研发确认。（落地约束：候选表须基于元数据/RAG 工具的真实查询结果，不得凭空编造表名。）

## 14. 第十一步：判断数据资产缺口

检查：是否缺原子指标来源、修饰词或标签、维度属性、DWS 汇总指标、DWM 主表或扩展表、是否只能先在 ADS 实现。

```text
核心、稳定、高复用 -> 优先沉淀 DWD / DWS
属性类维度 -> DIM
跨过程、多维度、灵活分析 -> DWM 主表
低频但属于明确分析主题的扩展字段 -> DWM 扩展表
探索性、临时性、不确定复用 -> ADS 并加注释标记
```

判断不清楚时不要强行决定，给建议和影响说明，让业务或研发确认。

## 15. 第十二步：复述指标口径，让业务确认

用自然语言复述口径，例：

```text
本指标统计的是指定观察日的新客借据余额。
其中，新客定义为首次放款日期在统计周期内的用户。
余额取借据余额快照中的当前未还本金。
统计周期按快照日期归属。结果按日期、渠道、产品维度聚合。
```

然后列出待确认问题（尽量二选一）：
```text
1. 新客按首次注册、首次授信，还是首次放款定义？
2. 余额取未还本金、剩余应还金额，还是账面余额？
3. 时间按自然日快照还是月末快照？
4. 是否排除测试用户、核销借据、已结清借据？
```

```text

- 原子指标来源表： 修饰词/标签来源表： 维度来源表： 时间字段： 关联键：

- 缺少标签： 缺少维度： 缺少汇总指标： 是否需要 DWM 主表： 是否需要 DWM 扩展表： 是否可以先放 ADS：

```

## 17. Agent 输出示例：新客余额

原始需求：`我想看一下新客余额，按渠道和产品分一下，最好每天更新。`

**指标拆解**：新客余额 / 存量型 / 借据余额快照·放款 / 原子指标=余额 / 每日快照 / 修饰词=新客 / 维度=渠道、产品 / 粒度=每天+渠道+产品 一行。

**口径复述**：每日快照时点的新客借据余额；新客暂按首次放款用户；余额暂按借据当前未还本金；按日期、渠道、产品聚合。

**待确认**：① 新客按首次注册/授信/放款？② 余额取未还本金/账面余额/剩余应还？③ 是否排除已结清/核销/测试？④ 渠道取注册/申请/放款渠道？⑤ 长期看板还是一次性分析？

**候选表**：原子指标→DWD 借据余额快照表/借据明细表；修饰词→DWS 用户标签表；维度→DIM 渠道表/产品表或 DWM 用户资产宽表；时间字段→快照日期；关联键→user_id、loan_id、product_id、channel_id。

**数据资产判断**：有 DWM 用户资产宽表且含余额+新客标签+渠道+产品 → 优先用；无 DWM 但 DWD 有余额、DWS 有新客标签 → 临时关联出数；新客标签不存在 → 判断是否沉淀 DWS 用户标签；仅临时分析 → 可先在 ADS 实现并加 metric_candidate 注释。

## 18. 核心原则

- 不直接相信业务口语化指标，要拆成指标体系语言
- 不直接拍板口径，要复述并让业务确认
- 不把维度误认为修饰词
- 不把统计型标签放 DIM
- 不让 DWD 反向依赖 DWS
- 不把所有低频字段塞进 DWM 主表
- 不确定是否沉淀中间层时，先给建议，再让业务或研发确认
- ADS 可以承接探索期逻辑，但必须注释标记，方便后续治理
